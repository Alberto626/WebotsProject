WHAT THIS DOES
- Uses the existing greenhouse scene, textures, and PROTO files.
- Adds a new controller, IrrigationAIReplay, and a separate test world.
- Reads one complete CSV input row about once per simulated second.
- Calls the existing Random Forest with the original feature names and order.
- Displays input values, AI pump code, and the recorded dataset pump code.
- Records predictions to a uniquely named CSV in the project's logs folder.
- Replays all 3,000 rows once; reset the simulation to restart the replay.
- Stops the original sensor controllers in this test world so their generated
  readings are not confused with the dataset inputs supplied to the model.

LIMITS AND NEXT STEP
This is an integration test on training-dataset inputs, not an independent model
evaluation or a working irrigation simulation. Dataset row order is not assumed
to represent time. No pump is actuated, no soil moisture dynamics are simulated,
and no water savings are measured. Codes 0 and 1 have NOT been assigned physical
ON/OFF meanings. The dataset does not document the soil-reading calibration.
The next step is to define explicit simulation assumptions and add feedback:
watering changes moisture, which changes future model inputs.

ENVIRONMENT
Requires the already-created project .venv with Python 3.12,
scikit-learn 1.6.1, pandas, and joblib. The new controller's runtime.ini uses
Patricia's current absolute Python path; edit it if the project is moved.
No activation or global Python preference changes are needed.
Keep the .python runtime folder in place: .venv depends on it.

FILES AND RESTORE
The original Agriculture.wbt, controllers, and PROTO files are not modified.
Reopen Agriculture.wbt to return to the original sensor simulation.
The test world still needs the existing project's protos and image files;
the patch ZIP alone is not a standalone greenhouse project.
Do not commit local .venv, .python, .tools, cache folders, logs, or an
absolute runtime.ini Python path to a shared repository.
